# Renaming "Codex Web GPT" to "Codex Superpower": inventory, Electron behaviour and migration plan

**Short answer:** the rename is safe if the build keeps the executable name "Codex Web GPT" and a few internal identifiers. The one hard trap: the updater installed on your Mac (86f2d311) refuses any build whose executable is not named "Codex Web GPT". It then rebuilds and fails again every hour, without end. Your ChatGPT sign-in does not depend on the app name. Cookie encryption is off, and no Keychain "Safe Storage" item exists.

**Sources.** All `file:line` references are at `91a38989`, which is origin/main and main-next, taken via `git archive`. The worktree `codex-superpower-wt` was switching branches during this work, which suggests another session is using it. The installed app is `86f2d311`. Its `source-update.cjs` and `source-update-worker.cjs` are byte-identical to main, and so are `profile.cjs`, `package.cjs` and both fork scripts. Branch `fork/codex-superpower-rename` (0fe41813) is already merged: it renamed the repository URLs only and kept the app name on purpose.

## 2. How Electron 41.10.7 derives the name, userData and Keychain entry (macOS)

The research agent read the v41.10.7 source; I checked the live facts on this Mac read-only.

**App name**
- `lib/browser/init.ts#L124-129` sets `app.name` from package.json `productName`, falling back to `name`.
- The packaged `app.asar/package.json` has no productName, so the app starts as `codex-web-gpt-launcher`.
- `main.cjs:88` then calls `setName("Codex Web GPT")` synchronously.

**userData**
- The default is `appData/<name>` (`shell/common/electron_paths.cc#L27-33`) and is cached the first time it is read.
- `app.setPath('userData')` always overrides it (`electron_api_app.cc#L956-967`).
- The app already pins the folder (`profile.cjs:31`, `main.cjs:95`). So changing productName or `setName` does not move the profile.

**Keychain entry**
- Service is `<app.name> Safe Storage`; account is `<app.name> Key` (Electron patch `feat_ensure_mas_builds…`).
- Both are fixed in `PostCreateMainMessageLoop` (`electron_browser_main_parts.cc#L519,#L559-562`). The main script's top level runs earlier (`#L277`), so the `setName` at `main.cjs:88` does decide the Keychain name.
- It does not matter on this Mac:
  - Fuse `EnableCookieEncryption` is 0. I read the fuse bytes `101100011` from the installed Electron Framework.
  - All 216–218 cookies in `Partitions/codex-web-gpt-chatgpt/Cookies` are plaintext (`value` set, `encrypted_value` empty). I counted on a copy and printed no values.
  - The launcher never calls `safeStorage`.
  - `security find-generic-password -s "Codex Web GPT Safe Storage"` finds no item.
- With the fuse off, Electron never sends a key to the network service (`system_network_context_manager.cc#L281-284`, `network_context_service.cc#L114-115`, `docs/tutorial/fuses.md#L38-49`).

**If cookie encryption were ever switched on:** a changed name means a new random key, old cookies fail to decrypt and are skipped, and there is no fallback (`sqlite_persistent_cookie_store.cc#1001-1012`). To stay safe, keep the name passed to `setName` stable before turning the fuse on, or add a test that pins the fuse off.

**Where macOS shows which name**
- **Bold menu-bar title:** `CFBundleName`.
- **About / Hide / Quit labels:** `app.name` at `will-finish-launching` (`menu-item-roles.ts#L69-73`).
- **About panel:** without `applicationName`, it uses `CFBundleName` (`browser_mac.mm#L605-622`).
- **Finder, Dock, Spotlight:** the file name wins whenever it differs from `CFBundleDisplayName` (Apple, "Display Names"). How the Dock labels a running app in that mismatch is UNVERIFIED.

**Do not override only `CFBundleName` via `mac.extendInfo`.** Electron finds its helpers by `<CFBundleName> Helper.app`, and would stop at launch with `LOG(FATAL) "Unable to find helper app"` (`electron_main_delegate_mac.mm#L58-65`). The helpers are named after productName (`electronMac.js:44-58,222`).

**How app-builder-lib 26.15.3 builds the macOS names**
- `productFilename` = `mac.executableName` ?? `executableName` ?? productName (`appInfo.js:55-57`; `macPackager.js:98-100` passes the mac options).
- `.app` folder = `${productFilename}.app` (`electronMac.js:229`).
- `CFBundleExecutable` = productFilename (`macPackager.js:357-359`).
- `CFBundleName` and `CFBundleDisplayName` = productName (`:366-367`). `extendInfo` is merged afterwards and can override them (`:404-406`).
- Helper apps follow productName.
- There is no separate option for the `.app` file name; it always follows `executableName`.

## 3. What depends on the bundle id — keep `dev.codexwebgpt.launcher`

**Privacy permissions (TCC)**
- Grants are keyed by bundle id (`client_type 0`) plus the stored code requirement.
- The app is ad-hoc signed: `Signature=adhoc`, no team ID, requirement `cdhash H"884905…"`. Every rebuild already fails that requirement.
- So TCC grants do **not** survive updates today, with or without a rename. Keeping the bundle id adds no new loss.
- Keeping grants across updates would need a stable signing identity. That is out of scope here.
- TCC.db: NOT_CHECKED (the database could not be opened read-only).

**Login item**
- Electron 41 on macOS 13+ uses `SMAppService mainAppService` (`platform_util_mac.mm#L74-79`).
- `sfltool dumpbtm` shows the record: Identifier `2.dev.codexwebgpt.launcher`, URL `/Applications/Codex Web GPT.app`, enabled.
- Whether the record follows a moved `.app` is UNVERIFIED, so re-register after a move.
- The startup check in `main.cjs:1289-1295` only acts when the OS reports a different on/off state, so it may not catch a stale path.

**Other things tied to the bundle id**
- **LaunchServices:** registered by path and bundle id.
- **Preferences:** `~/Library/Preferences/dev.codexwebgpt.launcher.plist`.
- **Automation consent:** AppleEvent consent for Terminal controlling the app.
- **Windows:** AppUserModelId.

**Keychain ACL:** not relevant, since no item exists.

**Recommendation:** keep the bundle id. Changing it would reset TCC, the login item, preferences and Automation consent for no benefit.

## 4. Migration plan

### How the installed 86f2d311 updater handles a renamed build

It builds the latest main with the new source's own scripts, then:

1. `findPackage` needs exactly one fresh `launcher/artifacts/codex-web-gpt-.+-mac-<arch>.zip` (`source-update.cjs:350-362`). If artifactName changes, the build fails, the commit is recorded as failed and automatic updates are blocked.
2. `findMacApplication` takes the first `*.app` in the stage, whatever its name (`:370-374`).
3. `readPackagedCommit` reads `sourceCommit` from `…/app.asar/package.json` (`:364-368`); the name does not matter.
4. The job gets `target = applicationBundle(process.execPath)`, which is **the old installed path**, and `executableName = "Codex Web GPT"`, the old launcher's own executable (`:582,633-635`).
5. The worker first requires `<staged>.app/Contents/MacOS/<old executable name>` (`worker:229`, `:93-95`). It writes its start marker only after that check (`:232`).
6. It then:
   - checks the `CodexWebGptSourceCommit` stamp (`:109-115`);
   - moves the old app to `rollback.noindex/<entry>/<basename of target>` (`:131-146`);
   - moves the new bundle to **the old path** (`:241-244`) and opens it (`:155-161`);
   - waits for "healthy" in the old userData health file.

**So:** the old updater always installs the new bundle at `/Applications/Codex Web GPT.app`. That is harmless for function, but Finder and the Dock keep the old name.

**A new executable name is fatal.** The worker exits before writing its marker, and `launchInstall` throws (`source-update.cjs:690-694`). `cancelInstall` then deletes the verified stage (`:706-709`), and no failed commit is recorded (that only happens at `:658`). The hourly check (`main.cjs:1407-1410`, auto-update defaults to on in `state.cjs:17`) repeats the full `bun run verify` build forever.

A health file written to a different userData would cause a rollback after 6 minutes. That cannot happen here because userData is pinned.

### Phase 2: move the bundle to `/Applications/Codex Superpower.app`

Only new code performs the move. The build artifact keeps the same shape, so a launcher that jumps straight from 86f2d311 to this commit still installs it at the old path. The move then happens at its next update. Phases 1 and 2 could ship together, but shipping Phase 1 first and checking it on this Mac is lower risk.

**`source-update.cjs`**
- Compute `destination`: if the current bundle's name is `Codex Web GPT.app` and it sits in `/Applications` or `~/Applications`, use the sibling `Codex Superpower.app`; otherwise leave it in place.
- Add `destination` to the job and keep `target` as the bundle being replaced.

**Worker**
- Stage the copy at `${destination}.updating-PID`.
- If `destination` exists and differs from `target`, refuse: record `install` / `destination-exists`, change nothing, relaunch `target`.
- Save `target` into the rollback folder, with meta `installedPath`.
- Move the new bundle to `destination` and open it.
- Read the executable name from the staged Info.plist `CFBundleExecutable`, falling back to `job.executableName`.
- When stopping the new launcher, look for processes under both executable paths (`launcherPids` currently checks one).
- On failure: move `destination` aside, restore the saved copy to the **original** `target` path, reopen it.

**Launcher, first start from a new path**
- If `autoStart` is on, call `setLoginItemSettings` again and check `getLoginItemSettings().status`.
- Record the last bundle path in `launcher-state.json`.

**`install-fork-macos.sh`**
- `APP=/Applications/Codex Superpower.app`; `LEGACY=/Applications/Codex Web GPT.app`. Stop if both exist.
- Find the new bundle as the one `"$STAGE"/*.app`; take its executable name from `CFBundleExecutable`.
- Save whichever bundle is installed, together with its `installedPath`.
- Install to `$APP`. On failure, remove `$APP` and restore to the original path.
- Quit with `tell application id "dev.codexwebgpt.launcher" to quit`; name-based lookup (`:157,188`) breaks after the rename.
- `pgrep` for both executable paths.
- Keep `USER_DATA` unchanged.

**`rollback-fork-macos.sh`**
- Detect the installed bundle at either path.
- Take the single `*.app` inside each rollback entry, which may now be named either way (`:37,44-45` hard-code the old name).
- Restore to the path the current bundle occupies, or `$APP` if none is installed. Never leave two copies.
- Quit via bundle id.
- An old local copy of this script would fail on entries named "Codex Superpower.app". Document that only the version from main should be used.

**Other files**
- `src/dev-chat/profile.ts:131-132`: add the new-path candidates.
- README / AGENTS: update the `/Applications/.../runtime/bin/codex-chatgpt-web` paths.
